## Μητρώο Πολιτών (Citizen Registry)

Εφαρμογή Spring Boot με REST API, αποθήκευση σε βάση H2 και αυτοματοποιημένοι έλεγχοι. Το έργο αποτελείται από τέσσερα Maven modules και χρησιμοποιεί Java 17.

## Απαιτήσεις

- JDK 17 
- Apache Maven 3.9 ή νεότερο.
- Διαθέσιμη θύρα TCP 8080 για τη REST υπηρεσία.

## Δομή του έργου


citizen-registry/
├── pom.xml
├── citizen-domain/             # Οντότητα πολίτη, δεδομένα ενημέρωσης, έλεγχος ημερομηνίας
├── citizen-service/            # REST API, JPA/Hibernate, H2 και έλεγχοι μονάδων
├── citizen-client/             # Διαδραστική εφαρμογή κονσόλας
└── citizen-integration-tests/  # Έλεγχοι REST API με Rest-Assured και Maven Failsafe


Όλα τα modules έχουν έκδοση '1.0.0' και χρησιμοποιούν το 'groupId' και το βασικό Java package 'com.citizenregistry'.

## Compilation και δημιουργια jar αρχείων για εκτέλεση

Από τον κύριο φάκελο του έργου εκτελούμε:

Σε bash:

mvn clean package


## Εκκίνηση της REST υπηρεσίας

Σε bash:

java -jar citizen-service/target/citizen-service-1.0.0-exec.jar


Η υπηρεσία είναι διαθέσιμη στη διεύθυνση 'http://localhost:8080/api/citizens'.

Η προεπιλεγμένη σύνδεση H2 είναι 'jdbc:h2:file:./data/citizensdb'. Ο φάκελος 'data/' δημιουργείται σχετικά με τον τρέχοντα φάκελο από τον οποίο ξεκινά η υπηρεσία και όχι σχετικά με τη θέση του JAR. Οι εγγραφές παραμένουν αποθηκευμένες μετά την επανεκκίνηση.


## Εκκίνηση της κύριας εφαρμογής με το μενού

Με τη REST υπηρεσία ήδη ενεργή, ανοίγουμε δεύτερο terminal και εκτελούμε:

Σε bash:

java -jar citizen-client/target/citizen-client-1.0.0.jar


Η εφαρμογή εμφανίζει το παρακάτω μενού, ελέγχει τα δεδομένα κατά την πληκτρολόγηση και παρουσιάζει μηνύματα σφάλματος σε περίπτωση που κάτι δεν εισαχθεί σωστά. Στο τερματικό η οθόνη καθαρίζεται μεταξύ των λειτουργιών και περιμένει να πατήσουμε Enter πριν επιστρέψει στο μενού.


1. Εισαγωγή πολίτη
2. Διαγραφή πολίτη
3. Ενημέρωση πολίτη
4. Αναζήτηση
5. Εμφάνιση πολίτη
6. Έξοδος


Οι επιλογές 1–5 εκτελούν τις αντίστοιχες λειτουργίες. Η επιλογή 6 ή οποιαδήποτε μη έγκυρη επιλογή τερματίζει την εφαρμογή.

Κατά την ενημέρωση, ο client ανακτά πρώτα τις υπάρχουσες τιμές ΑΦΜ και διεύθυνσης. Το **Enter διατηρεί** την αντίστοιχη τιμή, ενώ το '-' την **αφαιρεί**. Στη συνέχεια στέλνει με PUT και τα δύο πεδία, ώστε να μην χαθούν τιμές που δεν θέλουμε να αλλάξουμε.


Για σύνδεση με REST υπηρεσία σε διαφορετική port:

Σε bash:

java -jar citizen-client/target/citizen-client-1.0.0.jar --citizen.service.base-url=http://localhost:8081/api/citizens


## Διαθέσιμες λειτουργίες REST API

| Λειτουργία | Μέθοδος HTTP | Διαδρομή | Επιτυχής απόκριση |
|---|---|---|---|
| Εισαγωγή πολίτη | 'POST' | '/api/citizens' | '201 Created' |
| Διαγραφή πολίτη | 'DELETE' | '/api/citizens/{idCard}' | '204 No Content' |
| Ενημέρωση ΑΦΜ και διεύθυνσης | 'PUT' | '/api/citizens/{idCard}' | '200 OK' |
| Αναζήτηση | 'GET' | '/api/citizens/search?...' | '200 OK' (λίστα) |
| Εμφάνιση πολίτη | 'GET' | '/api/citizens/{idCard}' | '200 OK' |

### Εισαγωγή νέου πολίτη

Σε bash:

curl -i -X POST http://localhost:8080/api/citizens \
  -H 'Content-Type: application/json' \
  -d '{"idCard":"AB123456","firstName":"Γιώργος","lastName":"Παπαδόπουλος","gender":"Άνδρας","birthDate":"10-10-1970","afm":"123456789","address":"Αθήνα"}'


### Ενημέρωση με PUT

Μπορούν να ενημερωθούν **μόνο** το 'afm' και το 'address'. Το PUT πρέπει να περιέχει **και τα δύο** πεδία, ακόμη κι αν η τιμή κάποιου είναι 'null'. Κάθε PUT αντικαθιστά πλήρως αυτές τις δύο επεξεργάσιμες τιμές. Ο αριθμός ταυτότητας, το όνομα, το επίθετο, το φύλο και η ημερομηνία γέννησης δεν αλλάζουν.

Σε bash:

curl -i -X PUT http://localhost:8080/api/citizens/AB123456 \
  -H 'Content-Type: application/json' \
  -d '{"afm":"123456789","address":"Πάτρα"}'


Για διαγραφή του προαιρετικού ΑΦΜ με διατήρηση της διεύθυνσης, βάζουμε την τρέχουσα διεύθυνση:

Σε bash:

curl -i -X PUT http://localhost:8080/api/citizens/AB123456 \
  -H 'Content-Type: application/json' \
  -d '{"afm":null,"address":"Πάτρα"}'


Αν παραλείψουμε ένα από τα δύο πεδία, το αίτημα απορρίπτεται με '400 Bad Request'. Η τιμή 'null' ή το κενό κείμενο αφαιρεί το αντίστοιχο προαιρετικό πεδίο. Η επανάληψη του ίδιου PUT οδηγεί στο ίδιο αποτέλεσμα.

### Αναζήτηση πολιτών

Μπορούμε να χρησιμοποιήσουμε ένα ή περισσότερα από τα πεδία 'idCard', 'firstName', 'lastName', 'gender', 'birthDate', 'afm' και 'address'. Τα ονόματα και το φύλο συγκρίνονται χωρίς διάκριση πεζών/κεφαλαίων (case-insensitive). Η διεύθυνση αναζητείται ως τμήμα κειμένου, επίσης χωρίς διάκριση πεζών/κεφαλαίων (case-insensitive). Τα υπόλοιπα πεδία συγκρίνονται ακριβώς.

Σε bash:

curl -G 'http://localhost:8080/api/citizens/search' \
  --data-urlencode 'lastName=Παπαδόπουλος' \
  --data-urlencode 'birthDate=10-10-1970'


## Έλεγχος εγκυρότητας

| Πεδίο | Κανόνας |
|---|---|
| 'idCard' | Υποχρεωτικό, ακριβώς 8 χαρακτήρες χωρίς κενά, πρωτεύον κλειδί |
| 'firstName' | Υποχρεωτικό, έως 255 χαρακτήρες |
| 'lastName' | Υποχρεωτικό, έως 255 χαρακτήρες |
| 'gender' | Υποχρεωτικό, έως 255 χαρακτήρες |
| 'birthDate' | Υποχρεωτικό, πραγματική ημερομηνία σε μορφή 'dd-MM-yyyy', από 120 χρόνια πριν έως σήμερα |
| 'afm' | Προαιρετικό, ακριβώς 9 ψηφία όταν συμπληρώνεται |
| 'address' | Προαιρετικό, έως 500 χαρακτήρες |

Η ημερομηνία ελέγχεται τόσο σε επίπεδο client όσο και σε επίπεδο server. Για παράδειγμα, η '09-09-1000' απορρίπτεται, όπως και οι ανύπαρκτες ή μελλοντικές ημερομηνίες. Έχει οριστεί ένα όριο 120 ετών το οποίο υπολογίζεται εκ νέου κάθε ημέρα και ορίζεται στο 'BirthDateFormat.MAX_AGE_YEARS'.

Οι μη έγκυρες ή ελλιπείς τιμές επιστρέφουν '400 Bad Request', η αναζήτηση ανύπαρκτου πολίτη '404 Not Found' και η προσπάθεια δημιουργίας διπλότυπου ΑΤ '409 Conflict'.

Η αναζήτηση απορρίπτει άγνωστες, κενές, επαναλαμβανόμενες ή μη έγκυρες παραμέτρους. Τα POST και PUT απορρίπτουν άγνωστες ιδιότητες JSON. Οι έλεγχοι εκτελούνται και στον server, ανεξάρτητα από την εφαρμογή κονσόλας.

## Αυτοματοποιημένοι έλεγχοι

- **JUnit:** κατασκευαστές, ιδιότητες, ισότητα οντοτήτων, υποχρεωτικά πεδία, ΑΤ, ΑΦΜ, αυστηρή ανάλυση ημερομηνιών, μετατροπή JSON και έλεγχοι PUT.
- **Spring configuration:** εκκίνηση του Spring context και έλεγχος βασικών beans.
- **JPA/Hibernate:** αποθήκευση, ανάκτηση, ενημέρωση, διαγραφή, σύνθετα κριτήρια αναζήτησης και επανεκκίνηση με την ίδια βάση H2.
- **Rest-Assured:** POST, DELETE, PUT, GET και αναζήτηση, καθώς και περιπτώσεις μη έγκυρων δεδομένων, ελλιπούς PUT και απόρριψης PATCH.

## Περιεχόμενα του ZIP

Το ZIP περιλαμβάνει τον πηγαίο κώδικα, τα Maven POM, το παρόν 'README.md', το GitHub Actions workflow και τις βοηθητικές οδηγίες/scripts. Δεν περιλαμβάνει φακέλους 'target/', αρχεία '.class'/'.jar', ρυθμίσεις IDE ή δεδομένα H2.

## GitHub Actions – 2η εργασία (CI/CD)

Για την τελική εργασία 3688 έχει προστεθεί το workflow **`.github/workflows/ci.yml`**. Ο αγωγός εκτελείται **αποκλειστικά με `push` στον κλάδο `develop`**, κάνει checkout, build/packaging, JUnit unit tests και Rest-Assured API/integration tests, και ανεβάζει δύο ανεξάρτητα GitHub Actions artifacts με XML/HTML αναφορές.

- `unit-test-reports`: XML του Maven Surefire και αναγνώσιμη HTML αναφορά.
- `api-integration-test-reports`: XML του Maven Failsafe και αναγνώσιμη HTML αναφορά.

**Οδηγίες δημιουργίας GitHub repository, ανεβάσματος κώδικα, λήψης screenshot και τελικής υποβολής eClass:** [CI_CD_GUIDE.md](CI_CD_GUIDE.md).

Το πακέτο αυτής της έκδοσης περιλαμβάνει επιπλέον τον φάκελο `.github/workflows/`, τον βοηθητικό Python report generator και τον PowerShell δημιουργό του τελικού ZIP.
